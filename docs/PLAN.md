## ১. MVP-র "ডান" মানদণ্ড 🆕 (বদলানো)

**Peinados (স্প্যানিশ-অনলি সাইট):**
1. টপিক "Peinados" + ভাষা ES দিয়ে **≥ ৩০০ আইটেমের ভেরিফাইড টপিক্যাল ম্যাপ** তৈরি; ভেরিফিকেশন রিপোর্ট সবুজ (সেকশন ৩.৯)।
2. ডেডুপ মান: স্যাম্পল অডিটে **ভুল-মার্জ ≤ ৫%** এবং **মিস-করা-ডুপ্লিকেট ≤ ১৫%** (এগুলো আমার প্রস্তাবিত টার্গেট; গোল্ড-সেটে মাপা হবে — সেকশন ৩.১০)।
3. ম্যাপ থেকে **২০টি আর্টিকেল** (১২ Type A + ৮ Type B) — ২টি ব্যাচে — WordPress-এ publish/schedule।
4. প্রতি আর্টিকেলে ৫ পিন = **১০০ পিন**, রিয়েল Pinterest-এ পাবলিশড (Standard access লাগবে)।
5. ফরম্যাট-ইউনিকনেস পাস; কোনো ডুপ্লিকেট ইমেজ নেই; কোথাও প্রাইস নেই; CTA টেক্সট সর্বত্র একই; খরচ লগ ও ক্রেডিট লেজার মেলে।
6. **ইংরেজি স্মোক-টেস্ট** (আলাদা থ্রোঅ্যাওয়ে সাইট): ৩০ আইটেমের EN ম্যাপ + ২টি আর্টিকেল — শুধু প্রমাণ করতে যে EN পাথ কাজ করে।
7. অ্যাডমিনে: ইউজার লিস্ট, ক্রেডিট গ্রান্ট, জব/এরর লগ, খরচ-বনাম-ক্রেডিট ড্যাশবোর্ড (ফুল অ্যানালিটিক্স ফেজ ৭-এ)।
8. **ভাষা-অন্ধ রিভিউ কাজ করে:** প্রতিটি স্প্যানিশ কীওয়ার্ড/টাইটেল/আর্টিকেল/পিন-কপির পাশে বাংলা বা ইংরেজি গ্লস দেখা যায়; ভাষা-QA রিপোর্ট সবুজ (৫.১)।

## ২. আর্কিটেকচার (সংক্ষেপে; ডিটেইল v2 থেকে বহাল)

- **Next.js (App Router, TypeScript strict) + Supabase (Postgres, Auth, RLS, Storage, pgvector, pg_cron, pg_net) + Tailwind + shadcn/ui + Vercel।**
- লম্বা কাজ = **জব কিউ + ছোট স্টেপ**; শিডিউলার = **Supabase pg_cron → pg_net → Vercel API রুট** (Vercel Hobby-তে cron দিনে একবারই চলে, তাই)।
- **Provider-agnostic LLM লেয়ার** (Claude/OpenAI/Gemini) + টাস্ক-ভিত্তিক রাউটিং + ফলব্যাক + কস্ট ট্র্যাকিং।
- **মাল্টি-টেন্যান্ট:** প্রতিটি ডাটা টেবিলে `workspace_id` + RLS; সার্ভার জব `service_role` দিয়ে কিন্তু সবসময় `workspace_id` পাস করে।
- **ক্রেডিট:** reserve → commit/release, idempotency key।
- **pgvector** (Supabase-এ ফ্রি) — টপিক্যাল ম্যাপের সিমান্টিক ডেডুপের জন্য।

```
/src/modules/{llm,research,topical-map,silos,articles,products,images,wordpress,pinterest,jobs,billing,credits,analytics,i18n}
/src/lib            # supabase, crypto, utils
/supabase/migrations
/wp-plugin          # companion mu-plugin
/docs               # PLAN.md, ADRs
```

## ৩. 🆕 টপিক্যাল ম্যাপ ইঞ্জিন (সবচেয়ে গুরুত্বপূর্ণ মডিউল)

### ৩.১ ইনপুট
- **টপিক/কীওয়ার্ড** (যেমন `Peinados`), **ভাষা**: `ES | EN | ES+EN`, **লোকেল** (যেমন `es-MX`, `es-US`, `es-ES`; EN: `en-US`), সাইট (বিদ্যমান পোস্ট ইমপোর্টের জন্য), **টার্গেট সাইজ** (min–max; ১০০–৫০০+; হার্ড ক্যাপ প্ল্যানভিত্তিক), **টাইপ মিক্স** (যেমন ৭০% A / ৩০% B), **বাদ দেওয়ার তালিকা** (ব্র্যান্ড, বিষয়), মোড (**Fast** = স্ট্যান্ডার্ড API, **Economy** = Batch API, ৫০% সস্তা কিন্তু ঘণ্টা-ভিত্তিক দেরি)।
- **ES+EN হলে:** দুটো **আলাদা নেটিভ ম্যাপ** (অনুবাদ নয়) — `parallel_group_id` দিয়ে লিঙ্ক করা; দুই ভাষার জন্য আলাদা সাইট/প্রজেক্ট (SEO ও hreflang সহজ)। কোনো টপিক দুই ভাষায় মিললে "counterpart" লিঙ্ক রাখা যায়।

### ৩.৩ S1 — Facet Model (টপিকের "ডাইমেনশন" বের করা)
LLM + web search দিয়ে টপিকের **এনটিটি/ফ্যাসেট ট্যাক্সোনমি** তৈরি। এক কলে ৫০০ কীওয়ার্ড চাওয়া হবে না — ফ্যাসেট ধরে প্রসারণ হবে। উদাহরণ (Peinados, স্প্যানিশ):

| ফ্যাসেট | নমুনা মান |
|---|---|
| চুলের ধরন | rizado, liso, ondulado, fino, grueso, afro, con volumen |
| দৈর্ঘ্য | corto, mediano, largo, media melena |
| অনুষ্ঠান | boda, graduación, quinceañera, fiesta, trabajo, escuela, playa, gimnasio |
| কে | niñas, mujeres, hombres, adolescentes, novias, madrinas, bebés |
| টেকনিক | trenzas, recogidos, moños, coletas, semirecogidos, ondas, rulos |
| স্টাইল/ট্রেন্ড | elegantes, casuales, vintage, boho, retro, tendencia por estación |
| অ্যাক্সেসরি | pinzas, diademas, ligas, tocados, scrunchies |
| টুল/প্রোডাক্ট (Type B) | plancha, rizador, secador, cepillo térmico, fijador, moldeadores |
| মুখের আকৃতি | rostro redondo, ovalado, cuadrado, alargado |
| সময়/কঠিনতা | en 5 minutos, fáciles, rápidos, paso a paso |
| সমস্যা/কেয়ার | frizz, caída, cuidado, errores, mantenimiento |

ফ্যাসেট ট্রি **ইউজার দেখে এডিট করতে পারবে** (ফ্যাসেট যোগ/বাদ) — এটা ম্যাপের কভারেজ কন্ট্রোল করে।

### ৩.৪ S2 — ক্যান্ডিডেট জেনারেশন (পপুলার + লংটেইল + আনটাচড)
একাধিক সোর্স **প্যারালালে**, প্রতিটি `source` ট্যাগসহ:
1. **ফ্যাসেট × মডিফায়ার ম্যাট্রিক্স** (LLM + web search): প্রতি ফ্যাসেট-মানে ৩০–৮০ কীওয়ার্ড।
2. **প্রশ্ন-মাইনিং:** `cómo / qué / cuál / por qué / cuánto / cuándo` ইত্যাদি + "People Also Ask"-ধরনের প্যাটার্ন।
3. **কম্পিটিটর গ্যাপ:** টপ প্রতিযোগীদের পাবলিক sitemap/URL স্লাগ/টাইটেল থেকে তাদের কভার-করা টপিক; যা তারা কভার করেনি তা "আনটাচড" প্রার্থী।
4. **ট্রেন্ড/সিজন ওভারলে:** অনুষ্ঠান ক্যালেন্ডার (লোকেল অনুযায়ী: boda, graduación, quinceañera, Día de las Madres, Navidad…) + Pinterest ট্রেন্ডিং কীওয়ার্ড (সেকশন ৩.৭)।
5. **ম্যানুয়াল ইনপুট:** ইউজারের নিজের কীওয়ার্ড (সবসময় কোটা-মুক্ত, কিন্তু ডেডুপ-চেক হবে)।
6. **ঐচ্ছিক প্রোভাইডার** (`KeywordDataProvider` ইন্টারফেস): কীওয়ার্ড সাজেশন/ভলিউম/ডিফিকাল্টি/SERP (সেকশন ৩.৭)।

প্রার্থী সংখ্যা সাধারণত **চূড়ান্ত ম্যাপের ৪–৮ গুণ** — তারপর ডেডুপে কমে।

### ৩.৫ S3 — নরমালাইজেশন (সস্তা, নির্ণায়ক ধাপ)
`lowercase`, ডায়াক্রিটিক-স্ট্রিপ কী (`peinados fáciles → peinados faciles` — **শুধু ম্যাচিং কী; ডিসপ্লে টেক্সটে আকসেন্ট থাকে**), বাড়তি স্পেস/পাংচুয়েশন, স্প্যানিশ স্টপওয়ার্ড (`para, de, con, los, las, un, una, en`), স্টেমিং/লেমা, **টোকেন-সেট কী** (শব্দের ক্রম বদলালেও এক), একবচন/বহুবচন (`peinado/peinados`)। এই ধাপে **এক্স্যাক্ট ও নিয়ার-এক্স্যাক্ট ডুপ্লিকেট** মার্জ।

### ৩.৬ S4 — 🔑 সিমান্টিক ডেডুপ (একই অর্থ + একই ইনটেন্ট = একবারই)
ইউজারের মূল শর্ত: *"একই অর্থ ও ইনটেন্টের কীওয়ার্ড একাধিকবার নেবে না — ক্লেভারলি বাদ দাও।"* আমরা এটা **তিন স্তরে** করব:

**স্তর ১ — এমবেডিং ক্লাস্টারিং (pgvector):**
- প্রতিটি প্রার্থীর এমবেডিং (বহুভাষিক এমবেডিং মডেল — OpenAI/Gemini; বিল্ডে বেছে নাও ও স্প্যানিশে মান যাচাই করো)।
- **cosine ≥ τ_high** (শুরুতে ~০.৮৮) → "সম্ভবত একই" (গ্রাফ এজ); **τ_low ≤ cosine < τ_high** (~০.৭৮–০.৮৮) → **বর্ডারলাইন**।
- থ্রেশহোল্ড **গোল্ড-সেটে টিউন হবে** (৩.১০) — এগুলো স্টার্টিং গাইড, সত্য নয়।

**স্তর ২ — LLM ইনটেন্ট জাজ (বর্ডারলাইন জোড়া, ব্যাচে ২০–৪০ জোড়া/কল):**
প্রশ্ন: *"একটি পেজ কি দুটো সার্চ ইনটেন্টই সন্তুষ্ট করতে পারবে?"* আউটপুট (স্ট্রাকচার্ড JSON): `same | parent_child | related | different` + কারণ।
- **মডিফায়ার-সংবেদনশীলতা:** `para niñas` ≠ `para niños` ≠ `para mujeres`; `fáciles` ≠ `elegantes`; `sin plancha` ≠ `con plancha`; সংখ্যা/সময় (`en 5 minutos`); লোকেল-শব্দ (`cabello` / `pelo` — **একই**, অথচ আলাদা প্রদেশে প্রচলিত)।
- **সিনোনিম** (`fáciles / sencillos / simples`) → `same`।
- রেজাল্ট `kw_pairs` ক্যাশে (একই জোড়া দুবার জাজ হয় না)।

**স্তর ৩ — SERP-ওভারল্যাপ (গোল্ড স্ট্যান্ডার্ড — তবে সঠিক টুল দিয়ে):**
দুই কীওয়ার্ডের টপ-১০ URL-এ **৩–৪+ কমন** হলে গুগল তাদের একই ইনটেন্ট ধরছে।
- 🆕 **১২ অক্টোবরের পরীক্ষা (বিল্ট-ইন web search):** `peinados fáciles` বনাম `peinados sencillos` → ২টি কমন URL (একই YouTube প্লেলিস্ট + একই Airbnb পেজ) — সমার্থক, ইঙ্গিত মেলে। `peinados para niñas` বনাম `peinados para niños` → ১টি কমন URL — আলাদা ইনটেন্ট, ঠিক। **কিন্তু** ফলাফল ছিল গোলমেলে: ইংরেজি Wikipedia পেজ (`peineta`, `bouffant`), ভিন্ন দেশের Pinterest সাবডোমেইন (`ar./mx./co.`), Harvard ফিড — আর টুলটি US-ভিত্তিক, গুগলের আসল র‍্যাঙ্কিং নয়।
- **সিদ্ধান্ত:** বিল্ট-ইন সার্চের SERP-ওভারল্যাপ = **দুর্বল সহায়ক সিগন্যাল** (মূল ভরসা নয়)। আসল গোল্ড স্ট্যান্ডার্ডের জন্য **`SerpProvider` (লোকেশন=Mexico, ভাষা=es সহ)** ব্যবহার করব — DataForSEO-ধরনের সার্ভিস, বর্তমান সোর্সে স্ট্যান্ডার্ড SERP কোয়েরি ~$০.০০০৬ (থার্ড-পার্টি; যাচাই করো), অর্থাৎ ৬০০ কোয়েরিতে ~$০.৪। **এটা এখন ঐচ্ছিক নয়, ফেজ 2a-র জন্য সুপারিশকৃত।**
- বিল্ট-ইন সার্চ ব্যবহার করলে ফলাফল ফিল্টার করতে হবে (ভাষা, ডোমেইন-কোয়ালিটি, রিলেভেন্স), নইলে উপরের মতো আবর্জনা ঢুকবে।

**ফলাফল মডেল — "প্রাইমারি + ভ্যারিয়েন্ট", ফেলে দেওয়া নয়:**
- প্রতিটি `same`-গ্রুপ থেকে **একটি `primary`** (স্পষ্টতম/টাইটেলযোগ্য/সর্বোচ্চ ডিমান্ড-সিগন্যাল)।
- বাকিগুলো **`variants[]`** — আর্টিকেলে সেকেন্ডারি কীওয়ার্ড/হেডিংয়ে ব্যবহৃত হবে, কিন্তু **আলাদা আর্টিকেল হবে না**। (এতে ক্যানিবালাইজেশন এড়ায়, অথচ কভারেজ হারায় না।)
- **`parent_child`** (যেমন `peinados fáciles` ⊃ `peinados fáciles para niñas`): নিয়ম — চাইল্ডের নিজস্ব স্পষ্ট SERP/গভীরতা থাকলে **আলাদা আর্টিকেল**, নইলে প্যারেন্টের **সেকশন**। সিদ্ধান্ত `decision: separate | section_of_parent` + কারণ।
- UI-তে "Merged N variants" এক্সপান্ডেবল; ইউজার **Split / Merge / Promote variant to primary** করতে পারবে।

### ৩.৭ ডাটা-বাস্তবতা (সৎ কথা) এবং ঐচ্ছিক প্রোভাইডার
- শুধু LLM web search দিয়ে **আসল সার্চ ভলিউম/ডিফিকাল্টি পাওয়া যায় না**। তাই v1-এ প্রতিটি আইটেমে `demand_source: provider | estimate` লেবেল থাকবে; "estimate" মানে LLM-সিগন্যাল-ভিত্তিক `demand_tier 1–5` (সংখ্যা বানানো ভলিউম নয়)।
- **"আনটাচড" ট্যাগ = হিউরিস্টিক:** ডিমান্ড-সিগন্যাল আছে + টপ রেজাল্টে দুর্বল/থিন/ফোরাম-প্রধান/পুরনো পেজ + প্রতিযোগীরা কভার করেনি। UI-তে ব্যাখ্যা-ট্যুলটিপ সহ দেখাব; "ডাটা-ব্যাকড" দাবি করব না।
- **`KeywordDataProvider`/`SerpProvider` অ্যাডাপ্টার** — যেমন DataForSEO (সোর্স অনুযায়ী pay-as-you-go, নূন্যতম ডিপোজিট ~$৫০, স্ট্যান্ডার্ড SERP কোয়েরি ~$০.০০০৬ — **থার্ড-পার্টি সোর্স; যাচাই করো**)। **ফেজ 2a-র আগে $৫০ ডিপোজিট করে es-MX কভারেজ টেস্ট করো** — স্প্যানিশ ডেডুপ ও গোল্ড-সেটের সঠিক যাচাই এটার ওপর নির্ভর করে (ভলিউম-ডাটা পাওয়াটা বাড়তি লাভ)।
- **Pinterest Trends:** v5 ডকে "List trending keywords" এন্ডপয়েন্ট দেখা গেছে; **অ্যাক্সেস শর্ত, সমর্থিত রিজিয়ন (স্প্যানিশ দেশ) ও স্কোপ আমি যাচাই করতে পারিনি** — বিল্ডে `GET /v5/trends/...` চেক করো; কাজ না করলে ইউজারের হাতে ট্রেন্ড কীওয়ার্ড পেস্ট করার অপশন।
- Google Suggest-এর অননুমোদিত এন্ডপয়েন্ট স্ক্র্যাপ **ডিফল্টে বন্ধ** (শর্ত-ঝুঁকি)।

### ৩.৮ S5–S8 — ইনটেন্ট, টাইপ, স্কোর, সাইলো, টাইটেল, স্লাগ
- **ইনটেন্ট:** `informational | commercial_investigation | transactional | navigational`; **funnel stage**; প্রতি আইটেমে **একটি প্রাইমারি ইনটেন্ট** (মিশ্র হলে ফ্ল্যাগ)।
- **আর্টিকেল টাইপ:** commercial → Type B; "ideas/looks/estilos" → Type A; (টাইপ এক্সটেনসিবল — পরে how-to/guide যোগ)।
- **স্কোর:** `priority = f(demand_tier, competition_weakness, business_value(Type B), pinterest_fit(ভিজ্যুয়াল-নেস), seasonality, silo_role)`; ব্যাখ্যাসহ।
- **সাইলো আর্কিটেকচার:** পিলার (ব্রড হেড-টার্ম) → ক্লাস্টার → সাপোর্টিং লংটেইল; হায়ারার্কিক্যাল ক্লাস্টারিং + সাইজ-কনস্ট্রেইন্ট (টার্গেট **১৫–৪০ আইটেম/সাইলো**; বড় হলে সাব-সাইলো/একাধিক ব্যাচ); সাইলো নাম LLM-জেনারেটেড।
- **ইন্টারনাল লিংক প্ল্যান:** প্রতি আইটেম → প্যারেন্ট পিলার + ২–৫ সিবলিং; পিলার → সব চাইল্ড; অ্যাঙ্কর ভ্যারিয়েশন সাজেশন।
- **টাইটেল:** প্রতি আইটেমে ৩টি অপশন; Type A-তে **র‍্যান্ডম N** (কনফিগ রেঞ্জ; একই সাইলোতে একই N এড়ানো; গোল সংখ্যা কম) — যেমন `Los 27 Mejores Peinados para Cabello Rizado`।
- **স্লাগ:** কীওয়ার্ড-অনলি, kebab-case, ডায়াক্রিটিক→ASCII (`ñ→n`), **কখনো সাল নয়** (`\b20\d{2}\b` অটো-স্ট্রিপ, টেস্টসহ), সাইটে ইউনিক।

### ৩.৯ S9 — 🔑 ভেরিফিকেশন রিপোর্ট (ম্যাপ ডেলিভারির আগে বাধ্যতামূলক)
ইউজার ম্যাপ পাওয়ার আগে অটো-চেক চলবে; UI-তে **রিপোর্ট কার্ড** (পাস/ফ্ল্যাগ/ফেইল + কাউন্ট):

| চেক | কী যাচাই হয় |
|---|---|
| V1 ডুপ্লিকেট | কোনো দুই প্রাইমারির `norm_key` এক নয়; কোনো জোড়া τ_high-এর ওপরে নয় (অ্যাডজুডিকেটেড "different" ছাড়া) |
| V2 ক্যানিবালাইজেশন | সবচেয়ে কাছাকাছি ২০ জোড়ার তালিকা + ভার্ডিক্ট; ফ্ল্যাগড জোড়া ইউজারকে দেখানো |
| V3 কভারেজ | ফ্যাসেট-হিটম্যাপ — কোন ফ্যাসেটে আইটেম কম; **"Fill gaps"** বাটন টার্গেটেড জেনারেশন চালায় |
| V4 ইনটেন্ট ইন্টেগ্রিটি | প্রতি আইটেমে একটি স্পষ্ট ইনটেন্ট; মিশ্র ফ্ল্যাগ |
| V5 ভাষা/লোকেল | সব কীওয়ার্ড টার্গেট ভাষায়; ইংরেজি-লিকেজ নেই (ব্র্যান্ড বাদে); লোকেল-শব্দ সামঞ্জস্য |
| V6 বিদ্যমান কনটেন্ট | সাইটের WP পোস্ট/sitemap-এর সাথে মিলিয়ে `already_exists` / "আপডেট করো" ফ্ল্যাগ |
| V7 পলিসি-ফ্ল্যাগ | YMYL/মেডিক্যাল ক্লেইম (চুল পড়া চিকিৎসা ইত্যাদি), ব্র্যান্ড/সেলিব্রিটি নাম (ট্রেডমার্ক/পাবলিসিটি রাইট), নিষিদ্ধ টপিক |
| V8 স্বাধীন অডিট | **ভিন্ন প্রোভাইডারের মডেল** র‍্যান্ডম ১০% স্যাম্পল অডিট করে → **আনুমানিক ভুল-মার্জ/মিস-ডুপ রেট** রিপোর্টে দেখায় |
| V9 সাইজ ও ব্যালেন্স | টার্গেট রেঞ্জে কিনা; সাইলো সাইজ ব্যালেন্স; Type A/B অনুপাত |
| V10 নিয়ম | স্লাগে সাল নেই; N রেঞ্জে; টাইটেল দৈর্ঘ্য; স্লাগ ইউনিক |

**ফেইল হলে ম্যাপ "ড্রাফট" থাকে** — ইউজার ঠিক করে/ফিল-গ্যাপ চালিয়ে আবার ভেরিফাই করে।

### ৩.১০ ডেডুপ কোয়ালিটি মাপার ইভ্যাল (Phase 2-এর প্রথম কাজ)
- **গোল্ড-সেট (নেটিভ স্প্যানিশ রিভিউয়ার ছাড়া — Claude ভেরিফাই করবে):** Peinados-এর ~২০০–৩০০ কীওয়ার্ড-জোড়া (`same/parent_child/related/different`)। **প্রোটোকল:**
  1. জোড়াগুলো বানানো নয় — **আসল ম্যাপ-রানের প্রার্থী-পুল থেকে** স্যাম্পল (কাছাকাছি, বর্ডারলাইন, স্পষ্ট-ভিন্ন — তিন ধরনই)।
  2. **দুটো স্বাধীন মডেল** (ভিন্ন প্রোভাইডার) আলাদাভাবে লেবেল করে; একমত হলে গোল্ডে ঢোকে।
  3. দ্বিমত হলে **তৃতীয় পাস SERP-প্রমাণসহ** (পছন্দ: `SerpProvider` es-MX; বিল্ট-ইন web search নয়েজি — ৩.৬ স্তর ৩ দেখো): দুই কীওয়ার্ডের টপ রেজাল্ট তুলনা — একই পেজ/অনুরূপ টপ-রেজাল্ট হলে `same`, নইলে `different`।
  4. তারপরও অমীমাংসিত (আনুমানিক ≤ ১০%) জোড়া **`uncertain` হিসেবে মেট্রিকের বাইরে** — অনুমানে লেবেল নয়।
  5. ফেজ 2a-তে Claude Code এটা `eval/golden/es-peinados.jsonl`-এ তৈরি করে; রিপোর্ট-সহ তোমাকে সারাংশ দেয় (তোমার স্প্যানিশ জানার দরকার নেই)।
  6. **সীমা (সৎ কথা):** এটা "LLM-প্যানেল সম্মতি", নেটিভ গ্রাউন্ড-ট্রুথ নয় — আঞ্চলিক শব্দ/স্ল্যাং (es-MX) এ ভুল হতে পারে। ফলস্বরূপ মেট্রিক নিখুঁত সত্য নয়, **নির্ভরযোগ্য আনুমানিক সূচক**।
- ইভ্যাল স্ক্রিপ্ট: থ্রেশহোল্ড/প্রম্পট বদলালে precision/recall (মার্জ কোয়ালিটি) প্রিন্ট করে; **CI-তে রিগ্রেশন চেক**।
- টার্গেট (প্রস্তাব): মার্জ precision ≥ ৯৫%, recall ≥ ৮৫% — **LLM-প্যানেল গোল্ড-সেটের বিপরীতে মাপা**। বাস্তবে যা আসে তার ভিত্তিতে পুনর্নির্ধারণ।
- **লাইভ ফিডব্যাক:** পাবলিশের পর Search Console ডাটায় একই কোয়েরিতে দুটো আর্টিকেল র‍্যাঙ্ক করলে (ক্যানিবালাইজেশন) অ্যাডমিনে ফ্ল্যাগ → মার্জ/পুনর্গঠনের সুপারিশ। এটা নেটিভ রিভিউয়ারের অভাবের সবচেয়ে বাস্তব পরিপূরক।

### ৩.১১ স্কেল, গতি, খরচ
- **চাঙ্কিং:** প্রতি জব < ৬০ সেকেন্ড; ফ্যাসেট-ভিত্তিক প্যারালাল ফ্যান-আউট; রিজিউমেবল স্টেজ।
- **আনুমানিক সময়:** ~৫০০-আইটেম ম্যাপ Fast মোডে ~১০–৩০ মিনিট; Economy (Batch)-তে ঘণ্টা-ভিত্তিক।
- **আনুমানিক খরচ (রুক্ষ, যাচাই-সাপেক্ষ):** ~৫০০-আইটেম ম্যাপ ≈ **$২–৬** (সস্তা/মিড মডেল + ~১০০–৩০০ web search ($১০/১০০০ Claude ধরে) + এমবেডিং/অ্যাডজুডিকেশন)।
- **ক্রেডিট (প্রস্তাব, `credit_rates`-এ এডিটযোগ্য):** ম্যাপ = `১০ + ৫ × ceil(আইটেম/২৫)` (১০০ আইটেম ≈ ৩০ ক্রেডিট)।
- **ফ্রি-টিয়ার DB (৫০০MB) সুরক্ষা:** প্রার্থীদের এমবেডিং ডেডুপ শেষে **শুধু প্রাইমারিতে রেখে বাকি মুছে ফেলা**; পুরনো `map_runs`-এর কাঁচা প্রার্থী আর্কাইভ/ক্লিনআপ জব।
- **হার্ড ক্যাপ:** প্ল্যানভিত্তিক (ট্রায়াল: ৩০ আইটেমের প্রিভিউ ম্যাপ)।

### ৩.১২ ম্যাপ লাইফসাইকেল
- **ভার্সনিং:** `map_snapshots`; বড় বদলের আগে স্ন্যাপশট।
- **পরে বাড়ানো:** "Extend map (+100)" — বিদ্যমান আইটেম/লাইভ কনটেন্টের বিপরীতে ডেডুপ করে নতুন যোগ করে; অনুমোদিত আইটেম অক্ষত।
- **ম্যানুয়াল অ্যাড:** ইউজার কীওয়ার্ড যোগ করলে **একই ডেডুপ-চেক** চলে ("এটি আইটেম #123-এর সাথে একই ইনটেন্ট — মার্জ করবো?"); চাইলে **Force add**।

### ৩.১৩ 🆕 ম্যাপ রিভিউতে ভাষা-সহায়তা
ম্যাপ রিভিউ টেবিলে প্রতিটি কীওয়ার্ড/টাইটেলের পাশে **অনুবাদ-গ্লস কলাম** (বাংলা/ইংরেজি, টগলযোগ্য); মার্জড ভ্যারিয়েন্টের কারণও গ্লসসহ দেখায় ("`peinados sencillos` ≈ `peinados fáciles` — সমার্থক, SERP-এ ২টি কমন URL")। যাতে স্প্যানিশ না-জেনেও ইউজার সিদ্ধান্ত নিতে পারে।

## ৪. 🆕 ব্যাচ/সাইলো লেখার ওয়ার্কফ্লো (ম্যাপের পরের ধাপ)

### ৪.১ আইটেম স্ট্যাটাস ও "বাদ যেতে থাকা" লজিক
`proposed → approved → in_batch → writing → draft_ready → in_review → scheduled → published → pins_pending → done` (+ `rejected`, `already_exists`)

| ভিউ | যে স্ট্যাটাস দেখায় |
|---|---|
| **Remaining** (ডিফল্ট) | `proposed, approved, in_batch` |
| **In progress** | `writing, draft_ready, in_review` |
| **Completed** | `scheduled, published, pins_pending, done` — **Remaining লিস্ট থেকে সরে যায়** |
| **All** | সব (ইউজার চাইলে দেখে) |

- **শিডিউল বা পাবলিশ হলেই** আইটেম Remaining থেকে বাদ — তুমি যেমন বলেছ। সাইলো কার্ডে "১২/২৮ কমপ্লিট" প্রগ্রেস রিং।

### ৪.২ ব্যাচ
- **একটি সাইলো = একটি ব্যাচ**; বড় সাইলো (> ব্যাচ-সাইজ) হলে **একাধিক ব্যাচ** (ডিফল্ট ১০–২০ আইটেম/ব্যাচ; কনফিগ)।
- **অটো ব্যাচ সাজেশন:** পিলার আগে → হাই-প্রায়োরিটি ক্লাস্টার → সাপোর্টিং; ইন্টারনাল-লিংক ডিপেন্ডেন্সি মাথায় রেখে। প্যারেন্ট পিলার পাবলিশ না হলে "**লিংক ব্যাকফিল**" জব পরে লিংক বসায়।
- **ব্যাচ রান:** ব্যাচ বাছাই → **ক্রেডিট এস্টিমেট** → কনফার্ম (ক্রেডিট হোল্ড) → জব রান (Economy হলে Batch API) → রিভিউ কিউ → অ্যাপ্রুভ → publish/schedule (ড্রিপ প্ল্যান) → পিন স্টেজ।
- **ম্যানুয়াল ব্যাচ:** ইউজার নিজে আইটেম বেছে কাস্টম ব্যাচ বানাতে পারবে।

### ৪.৩ প্রজেক্ট ড্যাশবোর্ড ("পুরো সিস্টেম দেখা")
- ওপরে কাউন্টার: মোট / Remaining / In progress / Completed; **ম্যাপ সম্পূর্ণ করতে আনুমানিক ক্রেডিট**; **পেস প্ল্যানার** ("দিনে ৩টা পাবলিশ করলে ETA = X সপ্তাহ")।
- সাইলো কার্ড গ্রিড (প্রগ্রেস রিং, পরবর্তী সাজেস্টেড ব্যাচ), ক্যালেন্ডার (শিডিউল), "পরের ব্যাচ শুরু করো" CTA।
- ফ্যাসেট-কভারেজ হিটম্যাপ (কমপ্লিটেডসহ)।

## ৫. Stage 2 — Article Engine (সংক্ষেপে; v2-এর সব নিয়ম বহাল)

- **জব স্টেপ:** `research → blueprint → outline → sections(parallel) → assemble(HTML) → images → schema → qa → review ✅ → publish`।
- **সেমান্টিক SEO:** ম্যাপের `primary + variants + facet entities` আর্টিকেলের এনটিটি-আউটলাইনে ঢোকে; SERP-গ্যাপ → ইউনিক ভ্যালু; ফ্যাক্ট-গ্রাউন্ডিং (`facts[]` + সোর্স URL); ইন্টারনাল লিংক ম্যাপ থেকে।
- **Blueprint Engine:** ডাইমেনশন-র‍্যান্ডমাইজেশন + `fingerprint` ইউনিক (সাইটজুড়ে) + টেক্সট-সিমিলারিটি চেক + ক্লিশে-ব্যান লিস্ট (**স্প্যানিশের আলাদা লিস্ট**); বানানো ব্যক্তিগত অভিজ্ঞতা/টেস্টিং দাবি নিষিদ্ধ; "Add my note" স্লট।
- **Type A (Listicle):** হাইলাইটস → আকর্ষণীয় ইন্ট্রো → N আইটেম (সাব-টাইটেল + ১ ইমেজ + বর্ণনা: প্যারা/বুলেট/কালারড হাইলাইট) → FAQ → Conclusion → Schema (`ItemList`, `FAQPage`, `Article`, `BreadcrumbList`, `inLanguage`)। শব্দ-বাজেট `words_per_item = (target − fixed)/N`; রেঞ্জ ১২৫০–২৭৫০।
- **Type B (Amazon):** Quick Verdict (৩ ক্যাটাগরি পিক) → তুলনা টেবিল (**প্রাইস কলাম নেই**) → How We Evaluate → ডিটেইলড রিভিউ (স্পেক টেবিল, স্কোর বার, Pros/Cons, My Take, Who it's for, Skip it if) → Buying Guide + ডিসিশন ফ্লো → FAQ → Final Verdict → Disclosure। **CTA = `sites.cta_label` সর্বত্র একই**; `rel="sponsored nofollow noopener"`।
- **Amazon মোড:** (A) নিজের Creators API (শুধু তোমার সাইটে) (B) ইউজারের BYOK (C) ম্যানুয়াল (বেশি ক্রেডিট; **Amazon স্ক্র্যাপিং নয়**)। ⚠️ তোমার নিজের API কী অন্যদের সাইটে শেয়ার করা Amazon-এর শর্তে ঝুঁকিপূর্ণ — ডিফল্টে নয়।
- **QA গেট:** শব্দসংখ্যা, N, alt, ডুপ্লিকেট ইমেজ, H1, **স্লাগে সাল নেই, কোথাও প্রাইস/"$"/"€"/"MXN" প্যাটার্ন নেই, CTA টেক্সট হুবহু মেলে**, এনটিটি কাভারেজ, লিংক, readability/ক্লিশে, Blueprint ও টেক্সট সিমিলারিটি, ungrounded claim, schema ভ্যালিড, ক্রস-মডেল জাজ।
- **Batch API** বাল্কে (Economy); ইন্টারেক্টিভে স্ট্যান্ডার্ড।

### ৫.১ 🆕 স্প্যানিশ-অন্ধ রিভিউ — কনটেন্ট না-পড়তে-পারা মালিকের জন্য নিরাপত্তা
**ঝুঁকি:** রিভিউ গেটে তুমি স্প্যানিশ আর্টিকেল পড়ে ভুল ধরতে পারবে না — অথচ ওটাই পাবলিশ হবে। তাই গেটটা শুধু "মানুষ দেখুক" হলে চলবে না; টুলকে **ভাষা-অন্ধ রিভিউ সহায়তা** দিতে হবে (SaaS-এ যেকোনো ইউজারের জন্যও কাজে লাগে: সেটিংসে `review_language`)।
1. **ভাষা-QA (অটো, আলাদা মডেল):** ব্যাকরণ, লিঙ্গ/বচন মিল, আঞ্চলিক শব্দ (es-MX অনুযায়ী `cabello`, `peinado`…), অনুবাদ-গন্ধ/অস্বাভাবিক বাক্য, ইংরেজি-লিকেজ, বানান — স্কোর + ফ্ল্যাগ। লেখক-মডেল ≠ জাজ-মডেল।
2. **অনুবাদ-গ্লস:** রিভিউ এডিটরে প্রতিটি সেকশনের পাশে **বাংলা/ইংরেজি অনুবাদ** (টগল); টাইটেল, হেডিং, FAQ, মেটা ডেসক্রিপশন, পিন-কপি সবকিছুতে।
3. **ব্যাক-ট্রান্সলেশন চেক:** স্প্যানিশ → ইংরেজি অনুবাদ করে মূল আউটলাইনের সাথে মেলানো — অর্থ সরে গেলে ফ্ল্যাগ।
4. **ঝুঁকিপূর্ণ দাবির সারাংশ:** সংখ্যা, স্বাস্থ্য/মেডিক্যাল দাবি, ব্র্যান্ড/প্রোডাক্টের কথা — ইংরেজি/বাংলায় তালিকা, সোর্স URL সহ; ইউজার শুধু এগুলো যাচাই করলেই হয়।
5. **ট্রাফিক-লাইট:** সবুজ (সব চেক পাস) / হলুদ (ছোট ফ্ল্যাগ) / লাল (ব্লক)। **লাল হলে পাবলিশ বাটন বন্ধ।** প্রথম ২০ আর্টিকেল **ড্রাফট হিসেবে** WP-তে রেখে ধীরে পাবলিশ করা।
6. **ম্যাপ-রিভিউতেও গ্লস** (সেকশন ৩.১৩)।
7. **সীমা:** এগুলো ঝুঁকি কমায়, শূন্য করে না। প্রথম ব্যাচ পাবলিশের আগে যেকোনো ১টা আর্টিকেলের অনুবাদ-গ্লস নিজে পড়ে অর্থ-বিচার করো; সুযোগ হলে প্রথম কয়েকটা আর্টিকেল নেটিভ স্পট-চেকে দেখাও (সেকশন ১৪-র ১১ নং পয়েন্ট)।

## ৬. ইমেজ ইঞ্জিন (সংক্ষেপে; v2 বহাল + 🆕 স্প্যানিশ নিশের শিক্ষা)

- সোর্স: Pexels ✅, Pixabay ✅ (ডাউনলোড-করে-নিজের-সার্ভারে; ২৪ঘণ্টা ক্যাশ), Unsplash ⛔ (ফ্ল্যাগ OFF — হটলিঙ্ক/অটোমেশন শর্ত), Openverse/Flickr/Wikimedia ঐচ্ছিক (শুধু CC0/অনুমোদিত লাইসেন্স; **শর্ত বিল্ডে যাচাই**)।
- প্যারালাল সার্চ + সোর্স-মিক্স কোটা (এক প্রোভাইডার ≤ ৬০%) + ঐচ্ছিক ভিশন-চেক + **pHash ডেডুপ** (`UNIQUE(workspace, site, provider, external_id)` সহ)।
- 🆕 **স্টক সাইটের সার্চ ইংরেজিতে ভালো কাজ করে:** স্প্যানিশ আইটেমের জন্য ইমেজ-কোয়েরি **ইংরেজি (প্রাইমারি) + স্প্যানিশ (সেকেন্ডারি)** দুভাবে তৈরি; Pexels/Pixabay-এর `locale`/`lang` প্যারামিটার ব্যবহার। লংটেইল স্টাইলে (`trenza de raíz`) স্টক কম পেলে `needs_image` → ইউজার আপলোড বা পরিবর্তিত কোয়েরি।
- মানুষের ছবি: লাইসেন্সে "ব্যক্তি প্রোডাক্ট এন্ডোর্স করছে" ধারণা নিষিদ্ধ থাকতে পারে — affiliate আর্টিকেলে মানুষের ছবি ও প্রোডাক্ট রিভিউ মিশাতে সতর্ক (লাইসেন্স যাচাই)।
